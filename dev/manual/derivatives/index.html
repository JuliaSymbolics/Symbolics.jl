Derivatives and Differentials

A Differential(op) is a partial derivative with respect to op, which can then be applied to some other operations. For example, D=Differential(t) is what would commonly be referred to as d/dt, which can then be applied to other operations using its function call, so D(x+y) is d(x+y)/dt.

By default, the derivatives are left unexpanded to capture the symbolic representation of the differential equation. If the user would like to expand out all the differentials, the expand_derivatives function eliminates all the differentials down to basic one-variable expressions.

Symbolics.Differential — Type
struct Differential <: SymbolicUtils.Operator

Represents a differential operator.

Fields

  • x: The variable or expression to differentiate with respect to.

  • order: The derivative order. Can be rational for fractional derivatives.

Examples

julia> using Symbolics

julia> @variables x y;

julia> D = Differential(x)
Differential(x, 1)

julia> D(y) # Differentiate y wrt. x
Differential(x, 1)(y)

julia> Dx = Differential(x) * Differential(y) # d^2/dxy operator
Differential(x, 1) ∘ Differential(y, 1)

julia> D3 = Differential(x)^3 # 3rd order differential operator
Differential(x, 3)

Symbolics.NormalDerivative — Type
struct NormalDerivative{D<:IntervalSets.Domain} <: SymbolicUtils.Operator

Represents the normal derivative operator on a boundary piece Γ. Dn = NormalDerivative(Γ) applied to a trace u(t, Γ) (a call of a dependent variable whose spatial arguments are replaced by the domain Γ) gives Dn(u(t, Γ)), printed as Dn_Γ(u(t, Γ)): the trace of the normal derivative. That is, differentiate u along the outward normal of Γ, then evaluate on Γ.

Like Differential, applying a NormalDerivative only builds a symbolic term, with the operator as its operation and the trace as its single argument. The term is left alone by expand_derivatives, and Symbolics.substitute_in_deriv descends into it. This type does not check that the piece of the operator matches the piece in the trace; that is up to the consumer. Both are recoverable from the term: the operator's piece is operation(term).piece, and the trace's is among arguments(only(arguments(term))).

Fields

  • piece: The boundary piece whose outward normal the derivative is taken along.

Examples

julia> using Symbolics

julia> @variables t u(..);

julia> Γ = Symbolics.DomainSets.UnitInterval(); # any `DomainSets.Domain`; typically a named boundary piece

julia> Dn = NormalDerivative(Γ);

julia> Dn(u(t, Γ))
Dn_0.0 .. 1.0 (Unit)(u(t, 0.0 .. 1.0 (Unit)))
source
Symbolics.expand_derivatives — Function
expand_derivatives(O; ...)
expand_derivatives(O, simplify; throw_no_derivative)

Expands derivatives within a symbolic expression O.

This function recursively traverses a symbolic expression, applying the chain rule and other derivative rules to expand any derivatives it encounters. This includes the lazy applications built by the vector calculus operators Grad, Divergence, Curl and Laplacian.

Arguments

  • O::BasicSymbolic: The symbolic expression to expand.
  • simplify::Bool=false: Whether to simplify the resulting expression using SymbolicUtils.simplify.

Keyword Arguments

  • throw_no_derivative=false: Whether to throw if a function with unknown derivative is encountered.

Examples

julia> @variables x y z k;

julia> f = k*(abs(x-y)/y-z)^2
k*((-z + abs(x - y) / y)^2)

julia> Dx = Differential(x) # Differentiate wrt x
Differential(x, 1)

julia> dfx = expand_derivatives(Dx(f))
(2ifelse(signbit(x - y), -1, 1)*k*(-z + abs(x - y) / y)) / y
source
Symbolics.is_derivative — Function
is_derivative(x)

Return true if x is an unapplied derivative term, i.e. a symbolic expression whose operation is a Differential. Return false for everything else.

Applying a Differential does not differentiate immediately: D(x^2) is stored as the symbolic application of D to x^2 until expand_derivatives is called. This predicate is the test for "this node is still an unapplied derivative", and is the usual building block for finding them inside an expression.

Wrapper types are unwrapped first, so the Num that D(x) returns and the raw expression tree Symbolics.unwrap(D(x)) give the same answer. That holds for any registered wrapper (@symbolic_wrap), including Arr.

Two things to be aware of when calling it:

  • It only inspects the top node. D(x) + y is not a derivative term even though it contains one. Combine it with Symbolics.hasnode or Symbolics.filterchildren to ask about a whole tree.
  • A Differential applied to a Complex{Num} distributes over the real and imaginary parts rather than forming one derivative term, so is_derivative is false for it even though each part is a derivative.
julia> using Symbolics

julia> @variables t x(t);

julia> D = Differential(t);

julia> is_derivative(D(x))
true

julia> is_derivative(Symbolics.unwrap(D(x)))
true

julia> is_derivative(D(x) + x)
false

julia> is_derivative(expand_derivatives(D(x^2)))
false

julia> Symbolics.hasnode(is_derivative, D(x) + x)
true

See also: Differential, expand_derivatives, Symbolics.hasnode, Symbolics.filterchildren, SymbolicUtils.unwrap.

source
Note

For symbolic differentiation, all registered functions in the symbolic expression need a registered derivative. For more information, see the function registration page.

Symbolics.get_differential_vars — Function
get_differential_vars(e, varlist = nothing; sort::Bool = false)

Return a vector of differential variables appearing in e, optionally restricting to variables in varlist.

A differential variable is an expression where the operation is a Differential, such as D(u) where D = Differential(x).

Note that the returned differential variables are not wrapped in the Num type.

Examples

julia> using Symbolics

julia> Symbolics.get_differential_vars(expr; sort = true)

Vector Calculus Operators

Symbolics also provides multivariate differential operators for vector calculus: Grad (∇), Divergence (∇⋅), Curl (∇×) and Laplacian (∇⋅∇). Each is parameterized by E: Op{false} (the default, also constructed by Op(vars)) builds a lazy term with the operator as the head, which expand_derivatives expands, while Op{true} expands into Differentials eagerly at application. Grad composes with LinearAlgebra.dot and LinearAlgebra.cross into the other operators. Curl accepts two or three independent variables: on a 2-component field it produces the scalar curl D(vars[1])(v[2]) - D(vars[2])(v[1]), and on a 3-component field the usual vector curl:

julia> using Symbolics, LinearAlgebra

julia> @variables x y z u[1:3];

julia> ∇ = Grad([x, y, z]);

julia> ∇(x^2 + y^2 + z^2)          # gradient, lazily
(∇(x^2 + y^2 + z^2))[1:3]

julia> expand_derivatives(ans)     # expanded
(SymbolicUtils.array_literal((3,), 2x, 2y, 2z))[1:3]

julia> ∇ ⋅ u                        # divergence
∇⋅(u)

julia> ∇ × u                        # curl
(∇×(u))[1:3]

julia> (∇ ⋅ ∇)(x^2 + y^2 + z^2)     # Laplacian
∇⋅(∇(x^2 + y^2 + z^2))
Symbolics.Grad — Type

The multivariate gradient operator ∇ with respect to the independent variables vars.

Applying Grad to a scalar field f produces the vector of partial derivatives [Differential(vars[i])(f) for i in eachindex(vars)]. With check = true (default), vars are validated to be non-constant symbolic scalars of numeric symtype.

The expansion parameter E controls evaluation. Grad{false} — the default, constructed by Grad(vars) — produces a lazy symbolic term with the operator as the head so the structure of the expression is retained; expand_derivatives expands it to Differentials on demand. Grad{true} expands eagerly at application, returning a Vector{Num}.

Grad composes through LinearAlgebra: ∇ ⋅ v produces a Divergence, ∇ × v a Curl, ∇ ⋅ ∇ a Laplacian and v ⋅ ∇ a directional derivative which applies componentwise to vector fields.

source
Symbolics.Divergence — Type

The divergence operator ∇⋅ with respect to the independent variables vars.

Applying Divergence to a vector field v with as many components as vars produces the scalar sum(Differential(vars[i])(v[i]) for i in eachindex(vars)). Divergence is also produced by LinearAlgebra.dot(∇, v) for a Grad ∇, and composing it with Grad (∇ ⋅ ∇) produces a Laplacian. Constant vector fields have zero divergence.

See Grad for the meaning of E, the check keyword and the interaction with expand_derivatives.

source
Symbolics.Curl — Type

The curl operator ∇× with respect to two or three independent variables vars.

Applying Curl to a 3-component vector field v produces the vector [D(vars[2])(v[3]) - D(vars[3])(v[2]), D(vars[3])(v[1]) - D(vars[1])(v[3]), D(vars[1])(v[2]) - D(vars[2])(v[1])] where D = Differential. Applying it to a 2-component vector field produces the scalar (out-of-plane) curl D(vars[1])(v[2]) - D(vars[2])(v[1]). Curl is also produced by LinearAlgebra.cross(∇, v) for a 3-variable Grad ∇, and composing Curl with Grad (∇ × ∇) produces an operator whose application to any scalar field vanishes.

See Grad for the meaning of E, the check keyword and the interaction with expand_derivatives.

Curl stores arguments in a tuple for two reasons

  • It always stores either 2 or 3 independent variables
  • The return of (::Curl)(x) depends on N if either E or x is a wrapped type or non-symbolic array.

This can make the construction of Curl type-unstable if it is given a vector of independent variables as input, but allows calling the operation to be type-stable.

source
Symbolics.Laplacian — Type

The Laplacian operator ∇ ⋅ ∇ with respect to the independent variables vars.

Laplacian{E}(vars) constructs Divergence{E}(vars) ∘ Grad{E}(vars) and is also produced by LinearAlgebra.dot(∇, ∇). Applied to a scalar field it produces the sum of second partial derivatives; broadcast it over a vector field for a componentwise Laplacian.

See Grad for the meaning of E, the check keyword and the interaction with expand_derivatives.

source

Adding Analytical Derivatives

There are many derivatives pre-defined by DiffRules.jl. For example,

using Symbolics
@variables x y z
f(x,y,z) = x^2 + sin(x+y) - z
f (generic function with 1 method)

f automatically has the derivatives defined via the tracing mechanism. It will do this by directly building the internals of your function and differentiating that.

However, often you may want to define your own derivatives so that way automatic Jacobian etc. calculations can utilize this information. This can allow for more succinct versions of the derivatives to be calculated to scale to larger systems. You can define derivatives for your function via the macro:

@register_derivative my_function(args...) i begin
    # ...
end

where i means that it's the derivative with respect to the ith argument. args is the array of arguments, so, for example, if your function is f(x,t), then args = [x,t]. You should return an Term for the derivative of your function.

For example, sin(t)'s derivative (by t) is given by the following:

@register_derivative sin(t) 1 cos(t)

For more information see @register_derivative.
